# 工程性能与 5x 确定性报告（PostgreSQL 16 实测）

## 1. 计量单位定义

- **测试数据规模：** 单租户写入 `10000` 条通过 OCSF `v1.4.0` 校验的事件（覆盖 `1007, 1001, 4001, 3002, 4003, 1009`），导入全部 `32` 条受支持 SigmaHQ 规则。
- **`rule_evaluations_per_sec`（规则评估吞吐）：** `已评估规则数 (32) / 批处理挂钟耗时(秒)`，每条规则对 `10,000` 条事件执行一次完整参数化 SQL 查询与匹配归集。
- **`event_rule_checks_per_sec`（逻辑事件-规则对检查吞吐）：** `(32 × 10,000) / 批处理挂钟耗时(秒)`。
- **冷热区分：** 第 1 轮为**首次冷执行 (`cold_first_run`)**（包含新建 `RuleMatch`、`Signal`、`CandidateGroup` 落库写入开销）；第 2～5 轮为**幂等重跑 (`warm_idempotent_rerun`)**（验证唯一键幂等去重与结果稳定性）。

## 3. 首次冷执行 vs 幂等重跑（连续 5 轮确定性验证）

| 轮次 | 执行模式 | 挂钟耗时 (ms) | CPU 耗时 (ms) | 新建 `RuleMatch` | 幂等去重 `RuleMatch` | 新建 `Signal` | 库内总 `RuleMatch` | `rule_evaluations/s` | `event_rule_checks/s` |
| :---: | :--- | :---: | :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| Run #1 | `cold_first_run` | 220.523 | 61.557 | 20 | 0 | 20 | 20 | 145.11 | 1451096.36 |
| Run #2 | `warm_idempotent_rerun` | 179.887 | 46.832 | 0 | 20 | 0 | 20 | 177.89 | 1778893.70 |
| Run #3 | `warm_idempotent_rerun` | 186.151 | 57.239 | 0 | 20 | 0 | 20 | 171.90 | 1719034.93 |
| Run #4 | `warm_idempotent_rerun` | 206.817 | 73.652 | 0 | 20 | 0 | 20 | 154.73 | 1547264.39 |
| Run #5 | `warm_idempotent_rerun` | 190.791 | 62.892 | 0 | 20 | 0 | 20 | 167.72 | 1677225.39 |

- **首次冷执行 (`Run #1`)：** 耗时 `220.523 ms`，`145.11 rule_evaluations/s`（`1451096.36 event_rule_checks/s`），新建 `20` 条 `RuleMatch` 与 `20` 条 `Signal`。
- **幂等重跑 (`Runs #2..#5` 均值)：** 平均耗时 `190.911 ms`（P50 `188.471 ms`，P95 `204.413 ms`），平均 `168.06 rule_evaluations/s`（`1680604.60 event_rule_checks/s`）。
- **确定性核验结论：** 5 轮库内 `(primary_event_id, rule_id)` 集合完全一致 = **`True`**，重复 `RuleMatch` 数 = **`0`**。
- **资源占用：** Python 进程峰值 RSS `112.36 MiB`（增量 `0.0 MiB`），5 轮累计 CPU 时间 `0.3066 s`。
