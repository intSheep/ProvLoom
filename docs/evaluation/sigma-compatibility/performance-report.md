# 工程性能与 5x 确定性报告（PostgreSQL 16 实测）

## 1. 计量单位定义

- **测试数据规模：** 单租户写入 `10000` 条通过 OCSF `v1.4.0` 校验的事件（覆盖 `1007, 1001, 4001, 3002, 4003, 1009`），导入全部 `32` 条受支持 SigmaHQ 规则。
- **`rule_evaluations_per_sec`（规则评估吞吐）：** `已评估规则数 (32) / 批处理挂钟耗时(秒)`，每条规则对 `10,000` 条事件执行一次完整参数化 SQL 查询与匹配归集。
- **`event_rule_checks_per_sec`（逻辑事件-规则对检查吞吐）：** `(32 × 10,000) / 批处理挂钟耗时(秒)`。
- **冷热区分：** 第 1 轮为**首次冷执行 (`cold_first_run`)**（包含新建 `RuleMatch`、`Signal`、`CandidateGroup` 落库写入开销）；第 2～5 轮为**幂等重跑 (`warm_idempotent_rerun`)**（验证唯一键幂等去重与结果稳定性）。

## 3. 首次冷执行 vs 幂等重跑（连续 5 轮确定性验证）

| 轮次 | 执行模式 | 挂钟耗时 (ms) | CPU 耗时 (ms) | 新建 `RuleMatch` | 幂等去重 `RuleMatch` | 新建 `Signal` | 库内总 `RuleMatch` | `rule_evaluations/s` | `event_rule_checks/s` |
| :---: | :--- | :---: | :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| Run #1 | `cold_first_run` | 255.716 | 72.136 | 20 | 0 | 20 | 20 | 125.14 | 1251388.87 |
| Run #2 | `warm_idempotent_rerun` | 193.040 | 47.664 | 0 | 20 | 0 | 20 | 165.77 | 1657685.03 |
| Run #3 | `warm_idempotent_rerun` | 180.866 | 54.225 | 0 | 20 | 0 | 20 | 176.93 | 1769261.15 |
| Run #4 | `warm_idempotent_rerun` | 183.193 | 63.234 | 0 | 20 | 0 | 20 | 174.68 | 1746794.81 |
| Run #5 | `warm_idempotent_rerun` | 210.193 | 57.012 | 0 | 20 | 0 | 20 | 152.24 | 1522413.67 |

- **首次冷执行 (`Run #1`)：** 耗时 `255.716 ms`，`125.14 rule_evaluations/s`（`1251388.87 event_rule_checks/s`），新建 `20` 条 `RuleMatch` 与 `20` 条 `Signal`。
- **幂等重跑 (`Runs #2..#5` 均值)：** 平均耗时 `191.823 ms`（P50 `188.117 ms`，P95 `207.620 ms`），平均 `167.41 rule_evaluations/s`（`1674038.67 event_rule_checks/s`）。
- **确定性核验结论：** 5 轮库内 `(primary_event_id, rule_id)` 集合完全一致 = **`True`**，重复 `RuleMatch` 数 = **`0`**。
- **资源占用：** Python 进程峰值 RSS `108.5 MiB`（增量 `0.0 MiB`），5 轮累计 CPU 时间 `0.2984 s`。
